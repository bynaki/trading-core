# 커밋 절차

사용자가 커밋을 요청했을 때만 이 절차를 밟는다. 아래 순서를 건너뛰거나 바꾸지 않는다.

검증 4종(ruff check / ruff format --check / pyright / pytest)은 이 절차에 들어가지 않는다. 그것은
작업을 마친 시점에 코드를 고쳤을 때 이미 돌렸어야 하는 것이다(`AGENTS.md` "명령" 절).

## 1. TODO → DONE 이관

`docs/TODO.md`에서 제목에 `[done]`이 붙은 항목을 훑는다.

- 아직 열려 있는(`[done]`이 없는) 항목과 **더 이상 관련이 없는** `[done]` 항목은 `docs/DONE.md`
  끝에 그대로 옮기고 `TODO.md`에서 지운다.
- 관련 판단의 기준은 `<prefix>:<word>` 태그와 내용이다. 같은 `prefix`의 열린 항목이 있거나, 열린
  항목이 그 내용을 전제로 삼으면 관련 있는 것으로 보고 `TODO.md`에 남긴다.
  예: `logger:core`는 완료됐어도 `logger:server-transport`가 열려 있으면 남긴다.
- 옮긴 항목을 가리키던 `TODO.md` 안의 문구(예: 상단의 "열린 과제는 …" 요약)와 `AGENTS.md`의
  참조 위치(`docs/TODO.md`의 X → `docs/DONE.md`의 X)도 함께 맞춘다.
- 옮길 것이 없으면 아무것도 바꾸지 않는다.

## 2. 개인정보·보안 검사

커밋할 diff 전체(`git diff`, 새 파일은 내용 전체)를 확인한다.

- 개인정보: 이메일·전화번호·실명·계정 ID, 로컬 절대 경로(`/root/...`, `/home/<사용자>/...`)
- 비밀값: API 키·시크릿·토큰·비밀번호·개인 키, `.env`·인증서 같은 비밀 파일
- 취약점: 입력을 검증 없이 `eval`/`exec`/`pickle`/셸 명령에 넘기는 코드, 예외 메시지·로그로 새는
  민감 정보, 검증 없이 새로 추가한 의존성

발견하면 커밋하지 말고 사용자에게 알린 뒤 멈춘다.

## 3. 보고·승인

다음을 한 번에 보여 주고 사용자의 승인을 기다린다. 승인 전에는 커밋하지 않는다. 작업 계획이
승인되었어도 커밋 승인은 따로 받는다.

- 1단계 결과: `DONE.md`로 옮긴 항목의 태그 목록, 또는 "옮길 것 없음"과 남긴 `[done]` 항목과 그 이유
- 2단계 결과: 검사 항목별로 이상 없음 / 발견 내용
- 커밋할 파일 목록
- 커밋 메시지 초안(Conventional Commits — `feat:`, `fix:`, `docs:` 등, 한국어 본문)

## 4. 커밋

승인을 받으면 커밋한다.

- 파일은 `git add <파일>`로 이름을 지정해 스테이징한다(`git add -A`/`.` 금지).
- 스테이징 뒤 `git status`로 의도한 파일만 들어갔는지 확인한다.
- 커밋 후 `git status`와 `git log -1 --stat`으로 결과를 확인해 짧게 보고한다.
